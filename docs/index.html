DeepSeek-V4 Hybrid Attention from Scratch

How it was built

Part 1: Token-Level KV Compression

Build the compressor of DeepSeek-V4's attention: split a sequence into blocks of m tokens with a trailing remainder, form the overlapping 2m-token windows, turn compression weights and positional biases into a softmax over each window, fold every window into one KV entry, wrap it as a module, and add the per-head RMSNorm the report applies to queries and KV entries.

Part 2: The Lightning Indexer and Sparse Selection

Produce attention and indexer queries from one shared low-rank latent, score every preceding compressed block with the weighted multi-head ReLU index score, mask it causally, keep the top-k entries per query, and run shared key-value multi-query attention with attention sinks over the selected entries.

Part 3: CSA: Sliding Window Branch and Partial RoPE

Add the uncompressed sliding-window KV entries that restore local, fine-grained dependencies, apply RoPE to the last dimensions of queries and KV entries and undo the absolute part on each head output with a position-minus-i rotation, build the grouped output projection, and assemble the full Compressed Sparse Attention layer.

Part 4: HCA and the Hybrid Stack

Build Heavily Compressed Attention: the non-overlapping compressor with the larger rate m', dense shared key-value attention over every preceding compressed entry plus the sliding window, then interleave CSA and HCA layers into pre-norm decoder blocks and a small language-model stack.

Part 5: KV Cache and Efficiency

Store KV entries in the report's mixed BF16/FP8 format, build the heterogeneous per-layer cache that appends one token at a time and compresses a block the moment it completes, decode incrementally and verify it reproduces the full forward pass, then quantify the cache and FLOPs savings against a GQA8 baseline at one million tokens.
